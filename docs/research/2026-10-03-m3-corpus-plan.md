# M3 corpus plan (proposal, 2026-10-03)

**Label:** EXPLORATORY. **Status:** Proposed by Claude (not yet owner-approved). The catalogue, the sizes and the split decide what is measured, so they are pending owner items P14–P18 in `docs/DECISIONS.md` (DR-0056). Nothing below is built until the owner rules.

## 1. Scope of M3 ("dev split only")

- The catalogue of regression and benign patterns is fixed now, and every planned pattern is assigned to dev or test now, before any corpus data exist. The split therefore cannot leak (R5).
- M3 builds and runs only the dev split. Test-split patterns are built after M5's power table, before the M6 freeze; the execution guard refuses them until then (DR-0034).
- `patternId` is the independence cluster: one mechanism in one source context (Atomic CRM, a Prompt to Page export, or one open-source library). The same mechanism applied to two dialogs of the same app is one pattern with two items.

## 2. Sources

| Source (`CorpusItem.source`) | What | Notes |
|---|---|---|
| `seeded` | Mutation patches on the selected SPA (Atomic CRM, P14) and on de-branded Prompt to Page exports | Patches in `corpus/patches/`, generated by the mutation tooling from named operators |
| `oss-history` | Genuine break and fix pairs mined from component libraries and applications: a released version that broke an accessibility behaviour and the version that fixed it, both buildable, licence recorded | Radix primitives are used by Atomic CRM, so a Radix regression can be one app built against two library versions; others use a minimal fixture page |
| `reconstructed` | The owner's customer defects, rebuilt with anonymised provenance (R6) | Only if the owner supplies them (P18) |

## 5. Benign catalogue (P16)

| BenignType | Operator examples |
|---|---|
| WRAPPER_ELEMENT | Wrap a control or region in a non-semantic `div` or `span` |
| CLASS_RENAME | Rename Tailwind or component classes with no visual or semantic change |
| CSS_ONLY | Change colour, spacing or layout only |
| COPY_EDIT | Edit visible text that no journey expectation asserts |
| A11Y_IMPROVEMENT | Add a missing description, label a landmark, add `aria-describedby` to an error |
| EQUIVALENT_REFACTOR | Replace a component with equivalent markup and behaviour (for example, a Radix primitive with a hand-written equivalent) |
| TIMING_WITHIN_TOLERANCE | Delay a toast or a focus move by less than the declared tolerance |

The working BenignType descriptions stay as in the extract until the M6 freeze review (DR-0030).

## 6. Mutation tooling

- Named operators, one per mechanism or benign type. Each takes a file and a target (component and occurrence), and produces a unified diff in `corpus/patches/<item>.patch`, with a corpus item that records the operator, the target and the expected symptom or benign type.
- Each patch is checked to apply cleanly to the pinned base, and to build. A seeded regression is kept only if its base journey passes (the expectation holds in base).
- `npm run corpus -- validate` checks every item, and the split, against `corpus/split.json`.

## 7. Mining open-source regressions

- Search the issue trackers of mature primitive and component libraries (Radix primitives, shadcn/ui, React Aria, Headless UI, MUI, Chakra) for closed issues reporting an accessibility regression with a fixing pull request.
- Keep a pair only if the broken and fixed versions are both published or buildable, the licence is recorded, and the behaviour maps to a primary-analysis symptom.
- Record the issue, the break and fix versions or commits, and the licence in `provenance`.
