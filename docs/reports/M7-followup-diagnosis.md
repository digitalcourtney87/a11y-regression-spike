# M7 follow-up: diagnosis from retained evidence

2026-10-12. Read-only analysis after owner acceptance of PR14. No new Windows jobs, local execution of third-party fixture code, modified journeys, rescoring or changed verdicts. Source is run 38276928082, the archived blocks and frozen code at protocol-freeze-v4. [Selected traces](../research/m7-followup/trace-extract.json) retain every repetition of the five regression items; twins/unchanged controls remain in the full archived evidence audit.

## Findings

**Bootstrap #39189: the baseline goal is checked before focus moves.** In all three absent-leg baseline attempts, the one Enter goal check records the Open details button. At the end of the same step, focus is on dialog Details and the accessibility snapshot contains the open modal. The broken side remains on the button with no modal. The runner checks once after 300 ms; the pre-admission check waits 500 ms, and the present leg checks after 900 ms and reaches the baseline goal. This establishes a timing mismatch. The fixture uses Bootstrap's modal fade; animation is a plausible contributor, but the precise transition duration is not established by these records. Waiting longer and pressing Enter again are different interventions; no repeat activation or repair has been applied.

**Vuetify #22770: native focus does not carry the journey's required name.** Both legs initially focus an unnamed textbox/editable-text node on both releases. The accessibility snapshot includes a nested textbox named “Select an item Select an item”, but that is not the node returned by the focused-element read. The exploratory admission check only checked whether the DOM input was active, not the focused AX/MSAA name. The confirmatory journey requires “Select an item”; it therefore fails before the version-specific keyboard wrap is attempted. Matching the nested name in a snapshot would not prove that native focus has that name. The underlying cause of the unnamed native input remains to be established before any new journey or fixture is designed.

**Calendar #4620: May 2018 is present and announced earlier, but the later browse goal has no speech.** All three real-NVDA attempts on both releases show May 2018 after Space. The month is also in the captured speech of the activation step. After the focus-mode toggle and document-top action, every one of 60 browse attempts records no speech. The native absent leg still distinguishes the intended one-month baseline advance from the broken double advance. The AX snapshot has an application container. A mode/context mismatch is a hypothesis; the captured speech and DOM alone do not establish NVDA's internal mode. The current real-NVDA path also does not reproduce the native double advance, so fixing the later reading goal alone would not establish that regression under NVDA.

**Carbon #7861: selection succeeds on the baseline, but the later reading goal is not traversed.** All three real-NVDA baseline snapshots show selected/checked Alpha and Chosen Alpha. Native focus remains on the Alpha list item, and the 60 browse attempts record no speech. The broken side retains Chosen none and focus on the Choices editor, with repeated “Al” speech rather than document traversal. A mode/context difference between sides is a hypothesis. An unverified toggle is not evidence of entering browse mode; substituting another navigation strategy after failure would violate the frozen rule.

**Date-picker #5428: the declared focus defect is observed, but the journey makes it a reachability failure.** Every baseline attempt in both legs reaches February18; every broken attempt remains focused on February19. However, previous-day requires February18 as its until goal and has no focusOn expectation. The oracle's unreachable path fires before expectation evaluation, producing INTERACTION_FAILS_UNDER_AT or JOURNEY_BLOCKED rather than the declared FOCUS_NOT_MOVED. The existing journey contract says that a regression should generally change an expectation rather than the goal, except where reachability is itself the symptom (harness/src/runner/journeys.ts). This is a confirmed modelling mismatch. The frozen result remains a correct-symptom miss; it cannot be repaired retrospectively by changing its expected symptom or excluding the item.

## Evidence and limits

The recorded behaviours above hold across all three repetitions, not only one illustrative trace. The source checks, snapshots and native-focus readings are retained separately; their different success criteria are not interchangeable. No claim is made that a mode hypothesis or unnamed-input cause has been experimentally proved. The source code was inspected, not run locally.

Relevant frozen implementation: itemRun.ts goalTarget/runAtStep (300 ms absent,900 ms present, then one observation window); compare.ts base-not-reached/unreachable before expectations; goals.ts checks the current focused node by name; journeys.ts documents the goal/expectation distinction.

## Recommended next work

Calibrate goal timing, native-focus identity and browse-mode assumptions on known-answer pages before designing another measurement. A proposed exploratory pilot is in [M8-diagnostic-proposal](../plans/M8-diagnostic-proposal.md). Keep the 77-pattern result and v4 unchanged; future changes need their own protocol and independent evaluation. No third confirmatory expansion is proposed.
